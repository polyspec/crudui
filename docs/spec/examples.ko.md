# 예제

[English](examples.md).

외부 비교 환경은 Compose로 이미지·리소스·마운트·시작 준비 검사를 관리합니다.
`containerctl up`은 변경되지 않은 컨테이너를 재사용하고 로컬 HTTPS를 제공합니다.
같은 설정을 반복 적용해도 저장 데이터·경로·애플리케이션 응답이 유지되어야 합니다.

현재 예제는 버전 없는 공개 API를 사용합니다. `examples/cross-check-console`은
구현별 검증·렌더링 결과를 비교합니다. 폼 사용법은
[폼 작업 절차](../operations/forms.ko.md)에서 정의합니다.

정본 로컬 예제 진입점은 [`https://crudui.test/`](https://crudui.test/)입니다. 하나의
`List → Detail → Form → Save → List refresh` 파이프라인으로 제공합니다. 별도 벤치마크
화면은 `/benchmark/`이며 `/displays/`는 경로로 제공하지 않습니다. 목록·상세 단계도 같은
파이프라인에 포함됩니다.

현재 예제는 폼만이 아니라 세 가지 명세 종류를 모두 다룹니다. Go, PHP, Rust 패키지 예제는 하나의 예제 레코드
집합으로 폼, 목록, 상세를 렌더링하고, PHP 예제는 PHP 확장에서도 그대로 실행됩니다. 교차 검증 콘솔은 구현별 폼,
목록, 상세 렌더링과 검증을 비교합니다. 폼 비교 페이지는 모든 서버와 프레임워크에서 폼의 서버 렌더링과
클라이언트 렌더링을 비교합니다. 목록과 상세 표시는
[표시 형식](display-formats.ko.md)을 따릅니다.

콘솔은 검증기 프로세스가 정해진 종료 상태로 종료하고 응답 계약에 맞는
JSON 객체를 출력한 경우에만 응답을 인정합니다. 데이터 검증은 종료 상태
`0`, 불리언 `valid`, `errors` 배열을 사용합니다. 각 오류에는 문자열
`path`, `field`, `rule`, `message`와 `value` 항목이 있어야 합니다.
오류 배열이 비어 있을 때만 `valid`가 참입니다. 필드 누락, 잘못된 타입,
모순된 결과, 프로세스 오류, 시그널 종료는 비교 실패로 처리합니다.
콘솔은 누락된 필드를 채우거나 잘못된 값을 변환하지 않습니다.

로드 실패와 입력 실패는 데이터 결과와 별도로 검사합니다. 모든 검증기 CLI는
`2`로 종료하며 비어 있지 않은 문자열 `error`, `code`와 문자열 `at` 항목만
반환합니다. 콘솔은 이를 `failure: { code, message, at }`로 기록하고 언어 간
전체 기록을 비교합니다. 종료 상태가 다르거나 항목이 없거나 추가되었거나 값이
잘못된 실패 응답은 비교 실패로 처리합니다.

과거 구현 비교는 독립된 외부 작업 공간에서 실행합니다. 해당 작업 공간은
소스 커밋, 컨테이너 빌드 입력, HTTP 애플리케이션, 검증 보고서를 보존합니다.
패키지 테스트는 해당 파일을 가져오지 않습니다. 재사용 폼 검사기와 JSON 순서
검사는 `tests/form-inspector/`와 `tests/ordered-json/`에서 관리합니다.

프론트엔드 예제는 애플리케이션 빌드 시 저장소의 로컬 명세를 import합니다.
생성된 정적 애플리케이션은 폼 명세를 포함합니다.
