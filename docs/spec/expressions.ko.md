# 표현식 문법

[English](expressions.md).

이 계약은 TypeScript·PHP·Go·Rust의 조건식과 값을 반환하는 삼항식을 정의합니다.
디자인 설정과 조건부 검증의 표현식은 같은 토큰·AST·평가 계약을 사용합니다.
동작 스크립트는 애플리케이션 JavaScript이며 이 엔진에서 평가하지 않습니다.

## 0. 처리

렉서는 소스 문자열을 토큰으로 변환합니다. 파서는 토큰을 AST로 변환합니다.
평가기는 AST, 폼 데이터, 현재 필드 경로를 받습니다. TypeScript뿐 아니라
PHP·Go·Rust도 이 단계를 구현합니다. 평가는 `eval`을 사용하지 않습니다.

## 1. 토큰

| 토큰 | 패턴 | 예 |
| --- | --- | --- |
| `DOT` | `.` | `.field` |
| `DOT_DOT` | 점 두 개 이상 | `..field` |
| `ASTERISK` | `*` | `items.*.name` |
| `IDENTIFIER` | `[A-Za-z_][A-Za-z0-9_]*` | `status` |
| `STRING` | 작은따옴표 또는 큰따옴표 문자열 | `'active'` |
| `NUMBER` | 정수 또는 소수 | `42` |
| `BOOLEAN` | `true` 또는 `false` | `true` |
| `NULL` | `null` | `null` |
| `EQ NE` | `==` `!=` | `.status == active` |
| `GT GE LT LE` | `>` `>=` `<` `<=` | `.count > 0` |
| `AND OR NOT` | `&&` `\|\|` `!` | `!.enabled` |
| `IN NOT_IN` | `in` `not in` | `.country in [US, CA]` |
| `QUESTION COLON` | `?` `:` | `.enabled ? 'yes' : 'no'` |
| `LPAREN RPAREN` | `(` `)` | `(.a || .b)` |
| `LBRACKET RBRACKET COMMA` | `[` `]` `,` | `[US, CA]` |
| `WHITESPACE` | 출력에서 제외하는 공백 | 공백 |
| `EOF` | 입력 종료 | 입력 종료 |

## 2. 문법

파서는 비교식 하나에 비교 연산 하나를 허용합니다. 괄호는 논리식을 그룹으로
처리합니다. 삼항식 분기는 다른 삼항식을 포함할 수 있습니다.

```ebnf
expression = ternary ;
ternary = logic_or [ "?" ternary ":" ternary ] ;
logic_or = logic_and { "||" logic_and } ;
logic_and = negation { "&&" negation } ;
negation = "!" negation | comparison ;
comparison = primary [ ( "==" | "!=" | ">" | ">=" | "<" | "<=" ) compare_value
                       | ( "in" | "not in" ) value_list ] ;
primary = path | literal | "(" logic_or ")" ;
path = [ dots ] IDENTIFIER { "." ( IDENTIFIER | NUMBER | "*" ) } ;
dots = "." { "." } ;
compare_value = primary | IDENTIFIER ;
value_list = "[" value { "," value } "]" | value { "," value } ;
value = literal | IDENTIFIER ;
literal = STRING | NUMBER | BOOLEAN | NULL ;
```

비교 우변의 단독 식별자는 문자열입니다. 식별자 뒤에 점이 있거나 점으로
시작하면 경로입니다. 따라서 `.status == active`는 문자열과 비교하고
`.a < .b`는 필드 값을 비교합니다.

삼항식 분기의 문자열은 따옴표로 구분해야 합니다. 따옴표 없는 분기 식별자는
데이터 경로이므로 `.vip ? gold : plain`은 `gold`·`plain` 필드 값을 읽습니다.

표현식의 AST 깊이는 뿌리부터 가장 깊은 잎까지 최대 64 노드입니다. 괄호, 부정,
삼항식, 연산자는 각각 한 단계를 더합니다. `((.a))`는 세 단계이고
`.a || .b || .c`도 왼쪽으로 중첩된 `Binary` 두 개이므로 세 단계입니다. 더 깊은
표현식은 `Expression is nested more than 64 levels deep` 메시지의 파싱
오류입니다. 파서가 한도에서 멈추므로 어떤 입력도 파서나 평가기의 스택을
소진하지 못합니다.

## 3. 우선순위

낮은 순서부터 높은 순서입니다.

1. `?:`, 오른쪽 결합
2. `||`
3. `&&`
4. `!`, 다음 비교식 또는 부정식에 적용
5. `== != > >= < <= in not in`, 비교 연산 하나
6. 경로, 리터럴, 괄호로 구분한 논리식

예를 들어 `!.a == .b`는 `!(.a == .b)`를 의미합니다.

## 4. AST

노드 종류는 `Ternary`, `Binary`, `Unary`, `In`, `Path`, `Literal`, `Group`입니다.
경로는 식별자·와일드카드·숫자 인덱스 세그먼트를 포함합니다. 공통 고정 사례는
소스 위치를 제외한 의미 필드를 비교합니다. 토큰은 `type`, `value`, `literal`을
포함하며 토큰열은 공백을 제외하고 `EOF`로 끝납니다.
[공통 고정 사례 형식](../../tests/fixtures/expr/README.md)은 언어별 검사에 사용하는
직렬화 필드를 정의합니다.

## 5. 평가

조건 평가는 불리언을 반환합니다. 값 평가는 중첩 삼항식을 포함한 삼항식에서
선택한 분기 값을 반환하고, 다른 표현식에서는 불리언 조건 결과를 반환합니다.
조건맵은 선택한 값을 저장된 그대로 반환합니다. 삼항식 외부의 단독 경로는
폼 데이터 원래 값을 반환하지 않습니다.
조건 설정의 문자열은 이 문법으로 끝까지 파싱될 때만 표현식이고 그 밖의 문자열은
리터럴 값입니다.

논리 연산자는 단축 평가합니다. 포함 검사는 `==`와 같은 동등 비교를 사용하며
`not in`은 포함 결과를 부정합니다. 같은 스칼라 타입은 직접 비교합니다.
다른 스칼라 타입은 모두 숫자로 변환할 수 있으면 숫자로, 그렇지 않으면
문자열로 비교합니다. 대소 비교는 양쪽을 숫자로 변환합니다. 문자열은 앞부분의
숫자를 사용하며 숫자가 없으면 0을 사용합니다. 이 조건 변환은 숫자 검증 규칙과
별개입니다.

상대 경로 `.field`는 현재 필드의 형제 필드를 해석합니다. `..field`는 부모를
한 단계 더 이동하며 점이 하나 추가될 때마다 한 단계 더 이동합니다.
접두사가 없는 경로는 데이터 루트를 기준으로 해석합니다. 누락된 값은 조건에서
거짓입니다. 필드 기본값은 폼 데이터 연결 단계에서 준비하며 표현식 평가기가
기본값을 찾기 위해 명세를 불러오지는 않습니다.

이 변환은 조건을 평가하며 필수 입력의 존재를 판정하지 않습니다.
`required` 규칙은 빈 배열과 객체를 거부합니다. 숫자 0과 불리언 false는 해당
규칙에서 유효한 입력 값입니다. 컬렉션 개수와 표시 여부는 별도 계약이며
[빈 컬렉션](empty-collections.ko.md)을 참고합니다.

## 6. 불리언 변환

`null`, 누락된 값, `false`, 숫자 0, 빈 문자열은 거짓입니다.
`"0"`과 `"false"`를 포함한 비어 있지 않은 문자열은 참입니다.
배열과 객체는 빈 배열·빈 객체를 포함해 참입니다.

## 7. 와일드카드

`items.*.name` 같은 경로는 반복 항목을 해석합니다. 기본 평가는 필드 컨텍스트가
현재 행 인덱스를 제공하면 이를 사용합니다. 그렇지 않으면 남은 와일드카드를
후보 값으로 해석하며 하나라도 일치하면 비교가 참입니다. TypeScript 경로
평가기는 명시적인 `ANY`·`ALL` 전략도 제공하지만 해당 옵션은 공통 표현식
진입점의 계약에 포함하지 않습니다.

## 8. 조건맵

조건맵은 기본 키 외의 키를 선언 순서대로 평가해 처음 일치한 값을 반환합니다.
리터럴 키 `true`는 위치와 관계없이 다른 조건이 모두 실패한 후 기본값을
제공합니다. 일치한 조건과 기본값이 모두 없으면 null을 반환합니다.

```yaml
class:
  ".status == 'active'": status-active
  ".status == 'pending'": status-pending
  true: status-default
```

맵 값은 표현식 평가 없이 반환합니다. 기본 키가 아닌 각 키는 단독 조건과
같은 파서·평가기에서 처리합니다.

## 9. 검증

네 언어와 PHP 확장은 같은 표현식 고정 사례를 불러와 토큰열, 직렬화한 AST,
불리언 결과, 값 결과를 비교합니다. 거부하는 표현식은 파싱 오류 메시지로
비교하며 메시지를 보고하지 않는 확장은 파싱에 실패하는지만 확인합니다. 사례 생성기는 TypeScript 출력을 기록하며 적합성 검사는
각 구현을 다시 실행해 기대 결과와 비교합니다. 생성만으로 정확성이 입증되지는
않습니다. 기대 의미는 이 계약과 일치해야 합니다. 구현과 테스트 결과는
[기능 상태](../features.ko.md)에 기록합니다.

## 10. 지원하지 않는 연산

산술 · 함수 호출 · 메서드 호출 · 정규식 평가 · 대입 · 비트 연산 · 슬래시로 시작하는 루트 경로 · eval.

검증 규칙은 표현식 엔진과 별도로 정규식 매개변수를 받을 수 있습니다.
동작 스크립트는 조건 평가와 별도로 처리합니다.
