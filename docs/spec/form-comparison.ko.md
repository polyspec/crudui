# Polyspec 폼 비교

[English](form-comparison.md).

예제는 `examples/form-comparison/`에서 관리합니다. 화면에는 Polyspec 이름을
표시합니다. 브라우저 검사는 예제 내부의 `window.comparison` 제어 함수를 사용합니다.
로컬 컨테이너 파일과 검증 보고서는 `.form-comparison/`에 저장합니다.

## 서버 구현

PHP, Go, Rust는 같은 네이티브 폼과 JSON 요청 계약을 구현합니다. 각 서버가 요청을
파싱하고 해당 언어의 기존 v2 검증기를 실행하며 독립된 JSON 저장소에 저장한 후
재로드 시 계층을 구성합니다. 검증이나 저장을 다른 언어에 위임하지 않습니다.
Node HTTP 프로세스는 브라우저 파일을 제공하고 요청 바이트를 선택한 서버에 전달합니다.

화면에서 서버와 프레임워크를 선택합니다. 두 비교 폼은 선택한 서버를 사용하며
원본·수정본·현재 검증기는 표시한 소스 리비전과 일치합니다. Go와 Rust 실행 파일은
소스 리비전별로 빌드합니다. 모든 서버는 두 전송 방식에 같은 전체 처리 과정과
상호작용 검사를 실행합니다. 구현과 검증은 [기능 상태](../features.ko.md)에 기록합니다.

모든 서버는 네이티브 필드 순서와 ordered-json 문서 멤버 순서를 유지합니다.
불완전한 네이티브 제출, 잘못된 컬렉션 자료형, 잘못된 JSON, 지원하지 않는 전송
자료형은 저장 전에 거부합니다. 동등한 요청은 같은 ID, 부모 ID, 위치와 값을 저장합니다.
기존 검증 규칙은 표시 여부와 별도로 필수·선택 항목을 판단합니다.
서버, 비교 예제와 프레임워크마다 독립된 저장소를 사용합니다.
단일 폼 필드 값과 seq 식별자는 문자열입니다. 누락되거나 null인 단일 필드는 빈
문자열로 정규화합니다. 숫자·불리언·복합 자료형의 필드 값은 언어별 문자열 변환을
사용하지 않고 거부합니다. 체크박스 기본값은 문자열 `"1"`입니다. 요청 크기는 2 MiB,
네이티브 필드는 10,000개로 제한합니다. 예제는 파일 업로드를 받지 않습니다.
다국어 `title` 객체는 명세에 선언한 `ko`, `en` 필드를 받습니다. 숫자 인덱스와
다른 언어 필드는 네이티브 제출과 JSON 제출 모두에서 거부합니다.

## 폼 동작

예제는 사용자 제출 전에 기존 `ValidatorV2`를 실행합니다. 실패하면 전송을 중단하고
반환된 필드 오류를 표시합니다. 선택한 서버는 같은 spec을 독립적으로 검증합니다. 표시 여부는
검증을 변경하지 않습니다. 숨겨진 필수 필드의 빈 값은 실패하고 선택 필드의 빈 값은
허용합니다. 검증을 위한 예제 전용 필수 규칙, 값 제거, 자동 값 추가는 사용하지 않습니다.
공유 사례로 TypeScript, PHP, Go, Rust의 규칙을 검사합니다. 렌더링 검사는 별도로
표시 여부, 네이티브 이름, 편집을 확인합니다. 서버 검사의 잘못된 직접 요청은 서버
거부를 확인하기 위해 브라우저 검증을 거치지 않습니다.

원본 소스를 수정한 예제는 명시적인 빈 배열과 객체를 행 0개로 출력하고 각 빈
컬렉션에 추가 버튼을 표시합니다. 데이터가 없으면 초기 행을 생성합니다. 예제
컨트롤러는 중첩 컬렉션을 포함해 버튼이 속한 컬렉션에 행을 삽입하며 출력된 행을
제거하지 않습니다. 수정본은 `1e8702a` 기반의 별도 소스 커밋입니다. 수정 전 원본
키 예제와 배열 진단은 계속 선택할 수 있습니다. 수정본과 현재 런타임을 주 비교로
제공합니다. 소스 수정 커밋은 `78723bb`이며 구현·검증·배포 상태는
[기능 상태](../features.ko.md)에 기록합니다.

인수 기준은 빈 회사·스토어·부서 컬렉션, 네이티브 및 JSON 저장·재로드, 마지막 행
삭제 후 재추가와 신규 행 저장을 포함합니다. 영향을 받지 않는 형제 행의 ID와
부모 관계는 유지되어야 합니다.
컬렉션 표시 여부는 행 개수와 별도로 `design.show`를 따릅니다. 표시 여부를 변경해도
데이터와 캐시한 구조를 유지합니다. 행이 있는 컬렉션은 숨겨져 있어도 해당 행을
제출하며 명시적인 빈 컬렉션은 행 입력을 제출하지 않습니다.

수정 전 소스 비교는 수정하지 않은 원본 `1e8702a`와 현재 런타임 `b516226`에 동일한 13자리
키 데이터를 제공합니다. 회사, 스토어, 부서 필드와 네이티브 제출, 저장 레코드가
동일합니다. 원본 키 예제는 원본 공개 함수에 행 연산과 캐시 바인딩을 연결합니다.
원본의 기반을 검사하며 13자리 식별자 규칙을 대체한다는 근거로 사용하지 않습니다.

이전 배열 진단은 선택해서 확인할 수 있도록 유지합니다. 이 예제는 숨김 seq 필드를
추가하며 기본 비교 대상이 아닙니다. 소스와 결과는 검증과 검토가 완료될 때까지
유지합니다.

인수 기준은 숨김 seq 필드와 별도 식별자 제출을 허용하지 않습니다. 현재 원본 배열
예제는 숨김 seq 필드를 사용하므로 이 요구사항을 충족하지 않습니다. 이 예제의 진단
결과를 승인된 제출 계약에서 동일하게 동작한다는 근거로 사용할 수 없습니다.
모든 비교 자료는 확인할 수 있도록 유지합니다.

식별자 검사는 숨김 seq 컨트롤과 제출된 `company_seq`, `store_seq`, `department_seq`
필드가 없는지 확인합니다. 별도 픽스처는 ID를 `[5, 7, 1]` 순서로 저장합니다.
검사는 7 다음에 삽입, 신규 ID 저장, 하위 행 복사, 정렬, 재로드를 수행하며
기존 ID와 부모 관계가 유지되는지 확인합니다.

별도의 키 기반 입력 사례는 두 렌더러에 같은 키 객체와 숨김 식별자 필드가 없는
명세를 제공하고 네이티브 이름, 서버 파싱, 검증, 문서 순서를 검사합니다. 이 사례는
배열 컨트롤러의 제출 설계와 별도로 원본 렌더러의 기존 키 데이터 지원을 확인합니다.
원본 키 예제의 load, save, validate, reset 엔드포인트는 키 데이터 계약, 선택한 언어의 원본
검증기, 독립된 저장소를 사용합니다.

키 예제의 행 연산 검사는 하위 행이 있는 픽스처를 사용하므로 빈 컬렉션 출력이
다른 영속 저장 검사를 막지 않습니다. 별도 exact와 empty 검사는 빈 부서 컬렉션이
있는 픽스처를 사용합니다. 예제 컨트롤러는 명시적인 빈 값을 채우거나 제거하거나
다른 값으로 교체하지 않습니다.

원본 키 바인딩은 원본의 `composeProperties`로 구조를 합성하고 직렬화·복원한 후
원본의 `buildField`와 `makeTranslate`로 데이터를 바인딩합니다. 각 키 어댑터는
마운트 전에 합성 참조를 한 번 읽으며 이후 로더 호출은 실패합니다. 캐시 검사는 특정
세션 속성 대신 반복 데이터 주입, 템플릿 내용 유지, 로더 읽기 1회를 확인합니다.
추가한 애플리케이션 바인딩과 수정하지 않은 라이브러리 소스를 구분합니다.
각 프레임은 선택한 서버에 저장 데이터를 요청하기 전에 마운트하고 응답 데이터를 주입합니다.

Apple container가 React, Vue, Svelte 브라우저 빌드와 PHP, Go, Rust API를 제공합니다.
라이브러리 소스는 지정한 커밋의 Git 아카이브에서 생성합니다. 유지한 원본 스냅샷의 라이브러리 소스는
변경하지 않습니다. 유지한 배열 예제의 컨트롤러가 기존 버튼에 배열 삽입, 깊은 복사, 삭제,
정렬을 연결합니다. 현재 input 값을 읽고 복사한 하위 구조의 선언된 seq 필드를
초기화하고 네이티브 입력 속성과 조건 표시를 갱신한 후 결과 배열을 원본 렌더링
인터페이스에 전달합니다. 폼을 다시 마운트하지 않고 포커스와 스크롤 위치를 유지합니다.
화면은 추가한 컨트롤러를 표시합니다. 이 동작을 원본 라이브러리에 이미 구현된 기능으로 서술하지 않습니다.
이 예제의 폼 데이터와 생성된 input 이름에는 13자리 키를 사용하지 않습니다.

브라우저 페이지가 포커스를 공유하므로 프레임 검사는 순차 실행합니다.
원본 예제 컨트롤러는 새 입력으로 대체된 입력 렌더링을 취소합니다. 새 입력 이벤트
이후에 이전 렌더링의 필드 값이나 선택 위치를 복원하지 않습니다.
각 원본 예제 어댑터는 프레임워크가 DOM을 갱신한 후 `load`를 완료합니다. 컨트롤러는
그 시점에 프레임 지연 없이 입력 값과 포커스를 복원합니다.
같은 브라우저 검사로 모든 예제의 실제 중첩 input 이름, 현재 값 복사, 하위 행 독립 편집,
정렬, 데이터 교체, 서버 전송, 영속 저장, 재로드를 확인합니다. 어느 버전이든 실패한
항목은 실패로 표시합니다. 원본에 버튼 처리가 없었다는 사실만으로 자료구조가 행 연산을
지원할 수 없다고 판단하지 않습니다.

실패 결과는 추가한 예제 구성, 원본 렌더러 동작, 원본 API 지원을 구분합니다.
숨김 seq 필드는 배열 예제가 추가한 것이며 원본 렌더러의 필수 조건이 아닙니다.
빈 컬렉션 출력과 정확한 영속 저장은 같은 빈 행 생성 동작 때문에 실패할 수 있으며
별개의 결함 두 개로 계산하지 않습니다. 각 실패는 간단한 원인 설명과 펼쳐 볼 수 있는
검사 오류 원문을 표시합니다. 설명은 검사 결과나 종료 코드를 변경하지 않습니다.

검증 중에는 비교 구현, 소스 스냅샷, 실행 환경을 유지합니다. 저장소 정리는 검증과
결과 검토 이후에 수행합니다. 검사 실행 완료를 모든 요구사항의 통과로 처리하지 않습니다.
브라우저 실행기는 검사 실패, 결과 누락, 브라우저 오류가 있으면 종료 코드 1을 반환하고
보고서에 실제 결과를 유지합니다.

서버, 비교 예제와 프레임워크마다 독립된 JSON 저장소를 사용합니다. 회사, 스토어, 부서 테이블은
문자열 seq와 0부터 시작하는 순서를 저장하며 하위 테이블은 부모 seq를 저장합니다.
저장은 잠금과 원자적 파일 갱신으로 전체 계층을 교체합니다. 기존 ID는 유지하고 신규
ID는 증가하며 삭제된 ID는 재사용하지 않습니다. 저장된 하위 ID를 다른 부모에게
할당할 수 없습니다. 검증 실패 시 저장소를 변경하지 않습니다. 로드는 저장된 행과
부모 ID로 배열 또는 키가 있는 객체를 생성합니다.

13자리 구현의 기본 검증 경로는 네이티브 폼 제출입니다. 각 프레임은 네이티브 폼과
JSON 전송을 선택할 수 있습니다. 두 방식은 같은 JavaScript 검증, 선택한 서버 검증,
저장소 저장을 실행합니다. 자동 검사는 각 방식의 잘못된 제출, 저장 후 키 갱신,
삭제, 빈 컬렉션, 재로드를 실행합니다. 같은 유효 데이터를 폼과 JSON으로 저장하면
레코드, ID, 행 순서가 같아야 합니다. 동일한 키 구조의 JSON 제출은
파싱, 편집, 저장, 재로드에서 문서 멤버 순서를 유지한다는 명시적 계약이 필요합니다.
JSON 경로는 브라우저 요청, 서버 요청·응답, 저장소 JSON 파일에 ordered-json
`deb1b354`를 사용합니다. 행 객체 키를 정렬하지 않으며 이 계약을 위해 JSON 문법을
변경할 필요는 없습니다. 파싱·직렬화는 폼 생성, 검증, 저장 규칙과 분리합니다.
전송 모듈은 `Value` 노드를 기존 일반 객체 데이터 모델과 상호 변환합니다.
JSON 형태 검사가 끝날 때까지 빈 객체와 배열을 구분한 후 PHP가 객체 데이터를
검증기 배열로 변환합니다. 폼 행 키는 구분자를 포함한 문자열을 유지합니다.
JavaScript는 객체 멤버 순서를 변경하는 변환과 유한하지 않거나 안전한 정수 범위를
벗어난 숫자를 조용히 변경하지 않고 거부합니다. 폼 필드 값과 seq 식별자는 문자열을
사용하며, 응답의 숫자 메타데이터는 JavaScript의 안전한 정수 범위 내 유한 숫자를
사용합니다.
JSON 문서의 멤버 순서를 편집하면 요청하는 행 순서도 변경됩니다. 검사는 문서 순서를
편집하고 저장 결과와 화면의 순서가 변경되는지 확인합니다. 키 기반 제출 데이터에
순서 필드, 숨김 seq 필드, 다른 키 형식을 추가하지 않습니다.
네이티브 multipart 제출은 생성된 input 이름과 마지막 `_form_complete=1` 필드를
포함합니다. 각 서버는 이 필드가 없는 요청을 거부합니다. PHP는 입력 개수 제한으로
잘린 요청도 거부합니다. 누락된 체크박스는 빈 문자열로, 누락된 반복 컬렉션은 빈 컬렉션으로
처리합니다. JSON 요청은 `{ "form": ... }`을 사용하며 빈 컬렉션을 포함해 배열 진단의
반복 값은 배열, 키 예제의 반복 값은 객체로 표현합니다. 응답은 각 예제의 자료형을 유지합니다.
화면은 네이티브 필드, 서버 파싱 데이터, 정규화한 값, 저장한 행, 로드한 폼 데이터,
경로별 키 변경을 표시합니다.

화면은 소스 커밋, 서버와 프레임워크 선택, 실제 검사 결과를 표시합니다. 환경은 localhost
포트를 사용하며 수동 검토를 위해 실행 상태를 유지합니다. 운영 문서는 빌드, 시작,
검사, 종료 절차를 설명합니다.

순서 검사는 각 예제의 전송 계약을 사용합니다. 키 예제는 순서를 변경한 네이티브
필드와 문서 멤버 순서를 유지하는 JSON을 서버에 제출하고 저장과 재로드를 검사합니다.
배열 버전은 JSON 객체 키를 재귀적으로 정렬한 후 전송하고 재로드한 배열 순서도
검사합니다. 표준 JSON 자체는 추가적인 멤버 순서 계약을 정의하지 않습니다.
저장 레코드를 불러올 때는 파일의
물리적인 레코드 순서와 무관하게 명시적인 `position` 값을 사용합니다. 실제 포인터와
키보드 검사는 포커스, 선택, 스크롤, 체크박스에 따른 메모 표시를 확인합니다.

## 순서 유지 JSON 처리기 검증

처리기 검사는 JavaScript, PHP, PHP 확장, Go, Rust에 동일한 JSON 문서를 제공합니다.
파싱, 직렬화, 재구성 후 모든 깊이의 객체 멤버 순서, 배열 순서, 단일 값,
객체와 배열의 자료형을 비교합니다. 사례는 `5, 7, 1` 순서의 숫자 형태 멤버 이름,
저장된 13자리 키, 추가·복사한 행, 저장 후 키 교체, 행 순서 변경, 빈 컬렉션을
포함합니다. 제출 문서에는 별도의 식별자 필드나 순서 필드가 없습니다.

이 검사는 JSON 처리기가 기존 데이터 계약을 충족하는지 확인합니다. 예제의
브라우저·영속 저장 검사를 대체하지 않습니다. 런타임 연동은 두 전송 방식 모두
실제 폼 처리 과정 검사를 통과해야 합니다. 의존성 커밋과 소스 아카이브 해시는
비교 소스 정보에 표시합니다. 구현·배포 상태는 기능 상태에 기록합니다.
