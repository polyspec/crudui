# 폼 검증

[English](form-comparison.md).

이 계약은 중첩 폼의 HTTP, 브라우저, 영속 저장 검증을 정의합니다. 구현과 검증기는
이 저장소에서 관리합니다. 검증은 명시한 하나의 커밋을 사용하며 다른 체크아웃의
소스 파일을 읽지 않습니다.

## 소스와 환경

준비 명령은 깨끗한 작업 트리와 명시한 커밋을 요구합니다. 해당 커밋의 전체
저장소를 Git 아카이브 하나로 생성합니다. 메타데이터는 아카이브의 커밋과
SHA-256 해시를 기록합니다. 이미지 빌드는 압축을 풀기 전에 해시와 Git 아카이브에
포함된 커밋을 검증합니다. 검증기, 서버, 패키지는 모두 이 아카이브를 사용합니다.
커밋하지 않은 파일, 이전 저장소 리비전, 소스 패치, 다른 체크아웃의 파일은 후보
이미지에 포함되지 않습니다.

후보 데이터, 보고서, 이미지 태그는 배포 데이터와 분리합니다. 후보 빌드와 검사는
배포 서비스를 변경하지 않습니다. 후보 집계가 종료 상태 0과 `passed: true`를
기록한 후에만 배포할 수 있습니다.

이미지 생성 단계는 브라우저 프로세스를 시작하지 않는 컴파일과 소스 검사를
실행합니다. 이미지 생성 환경은 Chromium 샌드박스에 필요한 namespace 계약을
제공하지 않습니다. 이미지를 시작한 후 Chromium 프로세스 검사를 포함한 전체 소스
스위트를 비특권 애플리케이션 사용자로 실행하며 Chromium 샌드박스를 활성화합니다.
생성 단계 검사나 실행 단계의 전체 소스 스위트가 실패하면 후보 검증도 실패합니다.

## 구현과 요청

PHP, PHP 확장, Go, Rust는 동일한 컴파일, 렌더링, 검증, 영속 저장, SSR 요청 계약을
구현합니다. 각 서버는 자체 생성기와 검증기를 사용합니다. PHP 확장 프로세스는
`crudui.so`와 `ordered_json.so`를 로드하고 PHP 프로세스는 두 확장을 로드하지
않습니다. 클래스 출처, 모듈 해시 또는 저장소 커밋이 다르면 시작을 거부합니다.

공개 API는 `/api/{server}/{action}/{renderingPath}/{framework}`만 허용합니다. 공개
프로세스는 PHP 프로세스, PHP 확장 프로세스, Go 프로세스, Rust 프로세스를 각각
하나만 시작합니다. 허용한 요청은 선택한 프로세스의
`/api/{action}/{renderingPath}/{framework}`로 전달합니다. API에는 구현 리비전이나
데이터 구조 경로가 없습니다. `bindForm`과 `createForm`은 렌더링·편집 경로를
선택합니다. 키 객체는 반복 인스턴스 데이터를 정의하며 구현이나 URL을 선택하지
않습니다.

브라우저는 `bindForm`과 `createForm` 렌더링 경로를 실행합니다. 두 경로는 동일한
후보 커밋의 패키지, 같은 keyed 데이터, 같은 전송 계약을 사용합니다. 선택한 서버가
데이터와 독립된 템플릿 하나를 컴파일하고 브라우저가 이 템플릿을 JSON에서
복원합니다. `bindForm` 경로는 템플릿과 현재 데이터로 필드 모델을 계산합니다. 해당
응용 프로그램 컨트롤러는 입력과 행 작업 후 keyed 데이터를 갱신하고 필드를 다시
바인딩합니다. `createForm` 경로는 같은 템플릿으로 편집 폼 세션을 생성하고 데이터
교체와 행 작업에 세션을 사용합니다. 각 프레임은 저장 데이터를 요청하기 전에 폼을
마운트하고 기존 렌더링 경로에 데이터를 주입합니다. 컴파일 실패는 실패로 반환하며
브라우저가 대체 템플릿을 컴파일하지 않습니다.

전체 브라우저 행렬은 다음 48개 시나리오 보고서를 포함합니다.

- 서버 4개: PHP, PHP 확장, Go, Rust
- 프레임워크 3개: React, Vue, Svelte
- 전송 2개: 네이티브 multipart 폼, ordered JSON
- 렌더링 경로 2개: `bindForm`, `createForm`

모든 보고서는 동일한 명세, 컴파일한 템플릿, 데이터, 검사를 사용합니다. 네이티브
저장과 JSON 저장은 동일한 레코드, 식별자, 부모 식별자, 위치를 생성해야 합니다.
Ordered JSON은 모든 깊이의 객체 멤버 순서를 보존합니다.

## 구조, 데이터, 식별자

구조 컴파일, 인스턴스 데이터, 렌더링, 검증을 분리합니다. 컴파일한 템플릿은 레코드
값을 포함하지 않고 JSON으로 직렬화할 수 있으며 컴파일을 사용할 수 없어진 후에도
재사용합니다. 동일한 캐시 키의 반복 데이터 주입, 편집, 재마운트는 컴파일 요청을
추가하지 않습니다.

반복 컬렉션은 행 식별자를 키로 사용하는 객체입니다. 저장된 sequence는 `__`와
13자리 십진수와 `__`로 구성합니다. 저장 전 신규 행은 `__`와 13자리 소문자
16진수와 `__`로 구성합니다. 키는 부모 컬렉션 안의 행을 식별하며 객체 멤버
순서가 표시 순서를 결정합니다. 런타임은 키 문자열로 저장 여부를 추론하지 않습니다.

전송 데이터에는 숨김 sequence 컨트롤, 보조 식별자 필드, 순서 필드가 없습니다.
서버는 같은 부모 아래 저장된 행에서만 기존 키를 확인합니다. 확인되지 않은 키에는
새 sequence를 할당하고 범위가 명시된 키 변경을 반환합니다. 삭제된 sequence는 다시
사용하지 않습니다.

명시적인 빈 객체는 빈 컬렉션이며 행 컨트롤을 생성하지 않습니다. 컬렉션 데이터가
누락되면 초기 행 하나를 생성합니다. 표시된 빈 컬렉션은 추가 버튼을 제공합니다.
표시 상태 변경은 데이터를 생성, 제거, 전송하지 않습니다. 행이 있는 숨김 컬렉션은
해당 행을 계속 전송합니다.

## 브라우저 검사

각 시나리오 보고서는 다음 동작을 모두 검사합니다.

- 렌더링, 네이티브 이름, 숨김 식별자 컨트롤 0개
- 추가, 복사, 이동, 제거, 저장된 키 교체
- 5, 7, 1 순서의 비연속 저장 식별자
- 숨김 필수 필드를 포함한 클라이언트와 서버 검증
- 네이티브와 JSON 전송, 잘못된 요청 거부, 정확한 재조회
- 빈 회사, 스토어, 부서 컬렉션 전체 동작
- 부모 관계, 형제 식별자 유지, 삭제 ID 미사용
- 캐시 구조 재사용과 컴파일 요청 수 유지
- 초기 데이터 생성과 마운트 후 주입 비교

초기화 비교는 원본 HTML, 파싱한 DOM, 모든 속성, 현재 컨트롤 상태, 네이티브 필드,
ordered JSON 데이터, 포커스, 선택 범위, 요소와 의사 요소의 계산된 CSS, 검증 결과,
저장 레코드를 기록합니다. 식별자, 속성, 스타일, 값을 제거하거나 교체하지 않고 모든
단계에서 두 초기화 경로를 비교합니다. 반복 주입 결과는 동일해야 합니다.

포인터와 키보드 검사는 포커스, 선택 범위, 스크롤 보존을 확인합니다. 정적 브라우저
진입 문서 검사는 두 렌더링 경로와 모든 프레임워크를 확인하고 네 서버의 대응 문서를
SHA-256으로 비교합니다. 생성 검사는 모든 서버와 프레임워크의 한국어·영어 SSR
출력을 확인합니다.

## 실행기와 보고서

브라우저는 작업을 시작하고 호스트는 짧은 프로토콜 호출로 상태와 완료 보고서를
수집합니다. 장시간 행렬 전체를 하나의 DevTools 프로토콜 호출에서 실행하지 않습니다.
수집기는 현재 보고서, 보고서 시작 시각, 완료 보고서 수, 요청·응답 수, 마지막
요청·응답 시각을 기록합니다.

서버 실행의 절대 제한은 900,000밀리초입니다. 요청이 계속 실행 중이어도 경과 시간이
이 제한을 초과하면 수집기가 실행을 중단하고 실패합니다. 현재 보고서, 완료 보고서 수,
요청 수, 응답 수가 300,000밀리초 동안 변경되지 않아도 실패합니다. 두 실패는 현재
상태와 완료된 모든 보고서를 보존합니다.

완료된 서버 보고서는 시나리오 보고서 12개, 상호작용 검사 60개, 로드 전 마운트 검사
6개, 정적 문서 검사 6개, 브라우저·페이지 오류 0개, 두 렌더링 경로에 일치하는 하나의
후보 커밋, 900,000밀리초 이내의 실행 시간을 요구합니다. `passed` 필드는
boolean이어야 합니다. 실행 활동, 초기화, 시간 증거가 누락되면 보고서는
미완료입니다.

네 서버 집계는 서버마다 완료된 보고서 하나를 요구합니다. 시나리오 검사 960개,
상호작용 검사 240개, 마운트 검사 24개, 정적 문서 검사 24개가 모두 성공해야 하며,
네 서버의 대응 정적 진입 문서가 같고 성능 결과 4개가 모두 성공해야 합니다. 실패, 누락,
잘못된 형식, 불일치가 하나라도 있으면 `passed: false`와 종료 상태 1을 반환합니다.
실패가 0개인 완전한 집계만 종료 상태 0을 반환합니다.

## 추가 검증

생성 검증은 성공 결과 290개, HTTP 요청 411개, 서버·렌더링 경로·프레임워크 조합
24개를 요구합니다. 저장소 검증은 원자적 갱신, 잠금, 위치 기반 조회, 부모 관계,
파일 변경 없는 요청 거부, 전체 삭제, sequence 할당을 확인합니다. 타입 검증은 모든
서버에서 동일한 스칼라와 컬렉션 규칙을 확인합니다.

빠른 소스 검사는 보고서 정책 실패, 프로토콜 시간 제한 동작, 절대 실행 제한과 무진행
제한, 소스 아카이브 변경, 스냅샷 차이, 생성 캐시 동작, 요청 수 변경을 재현합니다.
이 검사는 전체 후보 행렬을 대체하지 않습니다.
